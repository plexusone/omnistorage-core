## [v0.6.0] - 2026-10-25

### Highlights

- Security release for the session and Redis packages: session IDs are validated and kept out of logs and errors, `SiteID` is enforced on every session operation, and the Redis backend requires TLS and a password for remote servers

### Breaking

- `session.ViolationEvent.SessionID` is deprecated and always empty; use the new `SessionRef` field. `SessionError.Details` and the violation and eviction logs use the key `session_ref` instead of `session_id` ([`6a98254`](https://github.com/plexusone/omnistorage-core/commit/6a98254))
- `kvsredis.New` returns an error wrapping `ErrInsecureConnection` for a non-loopback `redis://` URL, a `rediss://` URL without a password, or a URL with `skip_verify=true`, unless `Config.AllowInsecure` is set ([`080e710`](https://github.com/plexusone/omnistorage-core/commit/080e710))
- The kvs session backend refuses session IDs that `ValidSessionID` rejects (more than `MaxSessionIDLength` characters, or characters outside A-Z, a-z, 0-9, `-`, `_` and `.`): `Create` and `Update` return `ErrInvalidSession`, `Get` returns `ErrNotFound` and `Delete` is a no-op ([`8286ea3`](https://github.com/plexusone/omnistorage-core/commit/8286ea3))
- With `SiteID` set, `ControlledStore.Update` and `Touch` return `ErrNotFound` for a session stored for another site and `Delete` leaves it in place, and `DeleteByUserID` deletes only this site's sessions and returns an error when the underlying store does not implement `SessionLister` ([`f30e70d`](https://github.com/plexusone/omnistorage-core/commit/f30e70d))

### Upgrade Guide

- Violation handlers and log or metrics pipelines: read `event.SessionRef` instead of `event.SessionID`, and the `session_ref` key instead of `session_id`; compare a known session ID with `session.SessionRef(id)`
- Redis: use `rediss://:<password>@host:port` with certificate verification for any non-loopback server, or set `kvsredis.Config{AllowInsecure: true}` for a trusted network
- Custom session IDs: generate them with `session.GenerateSessionID`, or make sure they pass `session.ValidSessionID`; sessions stored under other IDs in the kvs backend can no longer be read and should be recreated
- Multi-site deployments: keep `SiteID` the same across the processes of one site, and use a session store that implements `SessionLister` (both bundled backends do) if you call `DeleteByUserID`

### Security

- The kvs session backend kept sessions and each user's session index in one key space and used session IDs from client cookies as given, so the ID `user:<id>` addressed a user's index: deleting it hid the user's sessions from `DeleteByUserID`. Session IDs are now validated, and `Get` and `Delete` act only on a stored session with that ID ([`8286ea3`](https://github.com/plexusone/omnistorage-core/commit/8286ea3))
- `ControlledStore` put the full session ID, a bearer credential, into violation log lines, `ViolationEvent.SessionID`, `SessionError` details and the eviction log, so anyone with access to logs, metrics or error reports could take over the session. These now carry a non-reversible reference (the first 8 hex characters of the SHA-256 of the ID) ([`6a98254`](https://github.com/plexusone/omnistorage-core/commit/6a98254))
- `ControlledStore` stamped `SiteID` on `Create` and checked it on `Get` only: `Update` wrote the session as given, so a session rebuilt without `SiteID` was stored for site "", and `Update`, `Delete` and `Touch` acted on sessions of another site sharing the backend. They now enforce the configured site and report a `site_mismatch` violation ([`f30e70d`](https://github.com/plexusone/omnistorage-core/commit/f30e70d))
- `ControlledStore.DeleteByUserID` passed straight through, so one site's "log out everywhere" also ended the user's sessions on every other site sharing the backend. With `SiteID` set it now deletes only this site's sessions ([`88f37e8`](https://github.com/plexusone/omnistorage-core/commit/88f37e8))
- `kvsredis.New` accepted any `redis://` URL, so a remote Redis could be used over plaintext and without authentication, exposing session data and tokens on the network. Non-loopback servers now require `rediss://` with certificate verification and a password ([`080e710`](https://github.com/plexusone/omnistorage-core/commit/080e710))
- The Redis backend's `List` built its `SCAN MATCH` pattern without escaping, so glob metacharacters in the key prefix or the requested prefix matched keys outside it, including other namespaces sharing the instance. The literal prefix is now escaped and keys outside the requested prefix are dropped ([`32c897b`](https://github.com/plexusone/omnistorage-core/commit/32c897b))
